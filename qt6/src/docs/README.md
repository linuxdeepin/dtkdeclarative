# QML 控件设计与渲染文档规范

## 目的与要求

这组文档用于连接设计与实现：读者不依赖现有代码，也应能大致画出控件的设计效果，并根据描述实现对应的布局、渲染元素和显示条件。正文面向设计人员和开发人员，用自然语言说明“什么条件下显示什么、位于哪里、是什么颜色和形态”；代码路径和属性名只用于追溯，不能代替设计描述。

每份说明必须覆盖背景、颜色、内容布局和状态变化。不能只给颜色表，也不能只解释已有代码。数值应足以复现；受系统主题、字体、图标或背景影响的值应说明来源，不能编造固定值。

控件子文档以已经过设计验证的设计或实现为依据。文档目标、编写方式和通用规则只在本主文档说明，子文档仅列自身适用范围、渲染事实和验证依据。不同控件或变体的样式不得直接互相套用。当前以已经过设计验证的 Button 为样例。只为已有明确依据的控件建立子文档；未验证的设计差异标记为待确认，不批量推导其他控件的样式。

## 文档结构与索引

| 文档 | 职责 |
|---|---|
| 本主文档 | 统一目的、文档结构、状态维度、效果术语、颜色规则、维护和验收要求 |
| [Button.md](Button.md) | 普通 Button 的外形、内容、各渲染元素的显示条件、颜色和参数；不覆盖选中、高亮变体 |
| [QML 维护约束](../qml/.AGENTS) | 简短约束代码与文档同步，引用本规范，不重复详细规则 |

每个控件使用同名子文档，例如 Button.qml 对应 Button.md。子文档按以下顺序组织；不适用项明确说明，无需创建空章节。

1. **适用范围与依据**：控件用途、变体边界、设计版本或已验证实现、使用前提及主文档链接。
2. **外形与内容布局**：尺寸、圆角、内外边距、图文排列、对齐、镜像、内容缺省、空间不足时的处理及尺寸变化。
3. **渲染元素与显示条件**：每个元素独立描述外观、位置、叠放关系、何时出现或消失、状态变化及降级效果。
4. **色值与几何参数**：给出能复现的数值和语义颜色来源，说明透明度、继承和回退。可与元素说明合并，避免重复两份相同矩阵。
5. **实现对应关系**：集中提供仓库相对路径和必要的属性映射，便于核对。
6. **复现与验收**：列出需要比对的组合、关键状态切换及验证记录；未做视觉验证时明确说明。

## 公共状态维度

| 维度 | 取值 | 含义 |
|---|---|---|
| 主题 | 亮色、暗色 | 当前控件使用的主题；默认场景下与应用主题一致 |
| 控件状态 | 普通、悬浮、按下、未激活、禁用 | 控件当前的交互或可用性状态 |
| 窗口模式 | 普通模式、水晶模式 | 样式选择的普通色族或水晶色族；水晶常用于半透明窗口，但不保证模糊能力可用 |

普通表示可用且没有其他更高优先级状态；悬浮表示指针停留在控件上；按下表示控件处于按压状态；未激活表示所属窗口不活跃；禁用表示控件不可操作。默认有效状态优先级为：**禁用 > 按下 > 悬浮 > 未激活 > 普通**。例如窗口未激活但控件仍报告悬浮时，按悬浮处理；不能同时套用两套状态色。

选中、高亮、扁平、可视焦点、图文显示方式是控件自身的附加条件，由子文档说明它们如何叠加或覆盖。内部阴影开关、加载器是否启用不是新的公共维度。水晶模式也不是毛玻璃效果本身。

实现对照：普通／水晶分别对应 CommonColor／CrystalColor，默认色族从父级继承，无父级时使用普通色族。控件主题由 ColorSelector 解析；若效果直接读取应用主题，子文档的基准场景应说明二者一致，不把人为覆盖后的混合主题视为已经验证。

## 公共渲染元素术语

| 元素或效果 | 外观含义 | 子文档必须明确的参数 |
|---|---|---|
| 背景填充 | 控件轮廓内部的底色；可为纯色或渐变 | 范围、圆角、颜色、不透明度；渐变方向和色标位置 |
| 外投影 | 位于轮廓后方、可向外延伸的阴影，表现控件与底面的距离 | 层数、颜色、模糊、扩散、水平与垂直偏移、叠放顺序 |
| 内阴影 | 位于轮廓内缘的阴影或高光 | 每道的颜色、方向、模糊、范围和裁切 |
| 内斜面 | 常由亮暗两道内阴影组成，表现凸起或凹陷的边缘 | 亮暗层位置、颜色、偏移及交互变化 |
| 描边 | 沿轮廓绘制的边线；内描边与外描边按位置区分 | 内外位置、线宽、颜色、圆角及占用空间 |
| 毛玻璃 | 对控件背后的内容进行模糊，再透过半透明填充呈现 | 采样范围、模糊半径、饱和度、圆角裁切、能力不可用时的结果 |
| 焦点框 | 表示键盘等交互产生的可视焦点，独立于普通描边 | 显示前提、颜色、线宽、间距、圆角和超出控件的范围 |
| 内容 | 文字、图标及辅助指示器 | 非空与显示模式条件、字体或资源来源、颜色、布局和对齐 |
| 整体透明度 | 对完整控件的合成结果统一改变不透明度 | 触发状态、数值及是否影响所有元素 |

标题使用元素或效果名称，如“毛玻璃”“内斜面”。元素开头的说明只描述外观和几何参数；窗口模式、主题和控件状态的限制统一写进渲染条件表，不放在总述段落中。渲染条件表首列统一为“窗口模式与主题”，明确列出普通亮色、普通暗色、水晶亮色、水晶暗色四种组合。先说明共同前提（例如面板被隐藏），再说明元素自身条件。不显示的组合明确写“不显示”或“所有状态均不显示”，不能留空，也不能只写“基础颜色透明”。缺少状态专属色时应按公共回退规则确定最终颜色；最终透明且没有其他可见颜色时写“不显示”。若未激活颜色混合等处理可能使其显现，应在对应表格单元格写明显示条件及不满足时不显示。不能因一个颜色槽为空或透明，就推断所有元素都不创建；文档中的“隐藏／不显示”默认指最终没有可见效果。

## 条件与参数的写法

用“水晶模式、暗色主题且未按下时显示两道内斜面，按下后隐藏”这样的句子表达条件。不要用内部布尔表达式代替说明，也不要单列与渲染元素重复的“功能开关矩阵”。每个元素必须同时说明显示与不显示的范围，不能只描述悬浮而遗漏普通、未激活和禁用。

子文档至少覆盖两种主题 × 两种窗口模式 × 五种控件状态。相同结果可合并为“其余状态同普通”，但例外要明确；不可仅写“回退”而不给目标。额外条件如焦点、选中、扁平、资源缺失和效果不可用，应描述与基础维度的组合关系。

尺寸默认以 QML 逻辑像素计，不能直接当作显示器物理像素。坐标以右为水平正方向、下为垂直正方向。应区分背景建议尺寸、控件隐式尺寸和显式尺寸，区分内容内边距与背景内缩。色表使用红绿蓝 0–255、Alpha 0–1 的 rgba 记法；“—”表示该场景没有可见效果，透明色是已定义的颜色，不是未定义值。

## 公共颜色选择与回退

颜色主要由 [FlowStyle.qml](../qml/FlowStyle.qml) 提供，解析顺序以 [dquickcontrolpalette.cpp](../../../src/private/dquickcontrolpalette.cpp) 的 getColor 与 getColorOf 为依据。以下顺序不能交换：

1. **确定有效状态**。未激活先用普通状态取色。禁用若有当前主题、当前色族的专属禁用色则直接使用；没有时，按当前主题、当前色族的普通状态取色，不继续沿悬浮或按下取色。
2. **先在当前主题内查找**。普通模式的悬浮或按下缺值时，回退到普通模式的普通状态。水晶模式的悬浮或按下缺值时，依次尝试水晶模式普通状态、普通模式对应交互状态、普通模式普通状态。水晶模式普通状态缺值时，回退到普通模式普通状态。
3. **最后才跨主题回退**。暗色主题内仍没有有效取值时，按相同查找顺序取亮色值，再将红、绿、蓝分别变为 255 减去原通道值，Alpha 不变。系统高亮色和系统高亮文字色按当前调色板解析，不作反色。缺少一个暗色悬浮值并不意味着立即反色，应先尝试暗色普通值。
4. **处理未激活颜色**。启用系统未激活颜色组时，通常在基础色上混合标准调色板的窗口背景色，亮色遮罩 Alpha 为 0.4，暗色为 0.6；若关联控件的未激活和激活调色板相同，则跳过混合。固定颜色不经过这条调色板规则。透明基础色经过混合也可能变得可见，子文档不能无条件把未激活等同于普通状态。
5. **应用元素可见条件与控件整体透明度**。颜色存在并不代表对应效果一定显示。元素自身 Alpha 和整体不透明度分别生效；各控件自行规定禁用是否降低整体不透明度，不把 Button 的 40% 推广到所有控件。

色值表中应直接列出五种有效状态，便于逐列核对；重复的数值可以引用同表普通列，但毛玻璃等效果的未激活例外应直接写明。

例如暗色普通按钮的悬浮投影缺少专属暗色值时，先得到暗色普通状态的透明色，不能把亮色悬浮的黑色投影反成白色。已定义的透明色会终止回退，不继续寻找其他颜色。

## 维护与验收规则

- 修改控件的颜色、布局、内容、渲染元素、显示条件或状态切换时，同步修改对应子文档；修改通用语义时更新本主文档，并检查已收录控件是否受影响。
- 子文档保留控件自己的事实，不复制通用规则。只对确有差异的行为说明例外和原因。
- 设计和实现不一致时记录差异及验证依据。本次以已经验证的 Button 实现补正文档；后续设计变更应同步实现和文档，不能悄悄改文档掩盖差异。
- 全部文件链接使用仓库相对路径。PR 的描述和文档索引应只列实际存在、已经完成的内容。
- 审阅时先验证正文是否能独立解释外观和条件，再核对源码的颜色、几何、内容及状态优先级；最终视觉比对记录主题、模式、状态、控件尺寸、显示缩放和窗口背景。
- 不将源码核对当作视觉验收。没有设计图或未运行界面时，明确记录验证范围；纯文档改动检查链接和差异即可，无需为了文档构建项目。
